## F1.3 统一截图任务（2026-09-21）

托盘 Screen/Select/Window、CmdOrCtrl+Shift+A/S/W 与编辑器截图按钮统一调用 `capture::start`。E 快捷键继续显示白板。原先未注册的 `capture_screen/select/window` 命令由正式注册的 `start_capture` 替代；没有修改白板文件格式。

### 命令与状态

- `start_capture({ kind: "screen" | "select" | "window" })` 返回任务：`id`、`kind`、`status`。
- 同时只执行一个任务。忙碌期间重复调用返回当前任务（包含实际正在执行的 kind），不排队、不启动第二个采集进程。
- `capturing` 最终转为 `ready`（包含 path）、`cancelled` 或 `failed`（包含 error）。`ready` 只表示截图文件已保存，不表示图片项目或编辑器已加载。
- `get_capture_task({ id })` 查询指定任务；省略 id 查询最近任务；没有匹配记录返回 null。
- 内存保留本次进程最近 32 项任务，退出后清空。这不是持久化历史；F1.5 负责项目存储。
- `capture-task-changed` 事件用于通知，查询是结果来源。当前面板每 500ms 串行查询最近任务，重开窗口仍能读到结果；原有固定等待 500ms 再发送 `image-prepared` 的路径已移除。F1.6 仍需实现基于项目 ID 的可靠加载。
- 任务结果先记录再展示。成功打开预览；失败打开编辑器显示错误；取消不切换窗口、不创建项目。晚到的展示回调不会抢到更新任务前面。

### 平台结果识别

macOS 使用同一个 `/usr/sbin/screencapture` 适配器，移除窗口采集中的 Cmd+Tab 脚本。执行前通过 Apple 的 [CGPreflightScreenCaptureAccess](https://developer.apple.com/documentation/coregraphics/cgpreflightscreencaptureaccess()) 查询权限；仅点击“设置屏幕录制权限”时请求授权，不自动更改系统权限。

命令成功退出且文件存在、图片尺寸有效才成功。交互模式中无文件、无错误输出且退出码为 0/1 归为取消；权限拒绝、错误输出、信号终止或无有效全屏文件归为失败。命令行无法区分交互模式中所有“无输出、无诊断”的异常退出与取消，这一限制需在后续原生采集替换中消除。

为保证结果可信，本项提前实现 F1.4 的后台阻塞任务、按任务 ID 命名、输出检查与失败残留清理。采集前隐藏自身窗口、失败恢复、多显示器回归仍待 F1.4；当前成功截图可能包含 DYD 自身窗口。

## F1.4 采集前隐藏与窗口恢复（2026-09-21）

- 采集在主线程完成窗口状态快照与隐藏后才启动。快照只包含原本可见且未最小化的 Webview 窗口，保留窗口实例、页面会话与原 DYD 焦点。
- 窗口状态读取失败时不隐藏任何窗口；部分隐藏失败时先回滚已处理窗口，再将任务标为失败，不启动采集。
- 取消、采集失败（含权限拒绝）、后台任务异常均走同一恢复路径：逐个显示原可见窗口，最后恢复原 DYD 焦点。原本隐藏、最小化的窗口不被打开，不重建已关闭窗口。
- 成功时恢复原可见的辅助窗口，主白板与旧预览继续隐藏，然后展示截图预览，保持原成功路径的行为。
- 某一窗口恢复失败不会阻止其他窗口恢复；错误通过原生提示展示。文件保存成功不会仅因窗口恢复错误而变成截图失败。
- 任务直到恢复结束才退出 capturing 状态。期间重复截图仍复用同一任务；应用内打开窗口、显示白板快捷键和权限请求暂不打开新窗口，避免旧恢复流程与新采集交叉。
- 失败时优先由已经恢复的编辑器显示错误；编辑器原先隐藏/未打开时使用原生错误提示，不为报错擅自打开编辑器。取消不报错、不展示结果窗口。
- 隐藏后在后台等待 200ms，让窗口合成器刷新；这不是采集系统提供的逐帧同步保证。系统文件/权限面板、外部程序焦点及用户通过系统操作强制重新显示窗口不由 Webview 快照管理。多屏、Spaces 和全屏动画仍需真实采集验收。
- 若主线程事件循环已经停止，无法恢复原生窗口，调度失败会记录为任务失败并输出日志；不承诺应用退出后恢复窗口。

验证：18 项 Rust 单元测试全部通过（新增 5 项窗口事务测试），覆盖取消/失败恢复、保留隐藏和最小化状态、焦点最后恢复、部分隐藏失败回滚、快照读取失败无副作用、单窗口恢复失败仍继续，以及成功路径的恢复策略。`cargo build --locked`、本地未签名 debug app 打包、lint 与格式检查通过。

原生回归：同时打开白板、设置和编辑器，在白板绘制矩形，从编辑器发起区域截图。权限拒绝后编辑器重新显示并获得焦点，返回白板时矩形和撤销记录仍保留。未修改系统授权；真实成功截图排除自身窗口、Esc 取消、多屏与 Spaces 仍待验证，不将 F1.4 标记为全部验收完成。


## F1.5 图片项目存储（2026-09-21）

项目位于配置的截图保存位置下 `projects/<id>/`：

- `original.bin`：原文件的逐字节副本，通过文件内容识别格式，不重编码；应用没有覆盖原图的写入接口。
- `project.json`：version=1、ID、名称、UTC 创建时间、原图像素宽高，以及旧截图导入来源路径。导入旧文件时用源文件修改时间作为历史时间。
- `thumbnail.png`：最长边 320px，保留透明度。
- 根目录 `index.json` 是可重建的列表快照；项目目录为事实来源。当前启动和刷新列表会扫描项目、检查必要文件并重建索引，大规模列表的缓存/分页留给 P3.1。

### 写入与恢复

先写 `.pending-<id>` 暂存目录，原图、缩略图及 JSON 完成后同步文件，再原子重命名项目目录；JSON 通过同目录临时文件替换。macOS 同步目录以提交目录项变更，跨进程文件锁串行化创建、导入和索引恢复。Windows/Linux 尚未完成平台验收。

启动时后台恢复，历史刷新时也可重试：完整暂存目录自动提交；不完整/冲突的暂存目录保留并显示警告；不支持的版本或损坏项目保留并跳过，不阻止其他项目读取。索引丢失或 JSON 损坏可重建。索引写入失败不会丢弃已提交项目；磁盘提交过程中出现同步错误时，下次扫描仍可识别已经落盘的目录。

拒绝包含目录跳转的项目 ID、符号链接项目资产及无效元数据。单张输入文件上限 128 MiB，解码尺寸每边最多 16384px，解码内存上限 128 MiB；超限或损坏图片返回错误，不创建历史项目。普通失败清理本次新建的暂存目录；进程中断留下的目录由恢复扫描识别，不直接删除。

### 截图与旧图导入

成功采集后才创建项目，项目完整提交后任务返回 ready，并附带 `project_id`。取消/采集失败不进入存储。项目保存失败时原始截图保留在原 images 路径供重试导入；成功时也保留这份兼容文件，因此初期会多占一份原图磁盘空间，不自动删除旧截图。

历史页提供刷新、旧截图目录导入和项目详情读取。导入只扫描当前保存位置下 images 的直接子文件，支持 PNG/JPEG/WebP/BMP/GIF/TIFF；不递归、不跟随文件符号链接，不移动或改写源文件。以来源路径和原图字节比对去重；已由新截图流程创建的 images 兼容副本也会跳过。单文件失败继续处理其他文件，并汇总提示。缩略图已落盘，历史缩略图展示和编辑器图像加载仍属后续任务。

IPC：`list_projects` 返回 projects/warnings；`get_project({ id })` 从磁盘重新校验并读取元数据；`import_legacy_projects` 返回 imported/skipped/warnings。所有磁盘操作在后台阻塞线程执行；无需开放任意路径写入或增加前端文件系统权限。
