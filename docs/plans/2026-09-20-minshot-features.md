# DYD 截图、图片处理与录屏开发计划

状态：逐项开发中。D0.3 基线样例与清单已建立；F1.1 代码与单元测试已完成；F1.2 窗口与页面分离已实现；F1.3 统一任务代码与测试已完成，真实采集和快捷键/托盘验收待完成，F1.4 窗口隐藏/恢复已实现；F1.5 项目存储和恢复已实现，真实采集闭环验收待完成，见回归基线。依赖升级代码已在 `0597adb` 提交。

## 目标与保留范围

在现有 DYD 上逐项增加 MinShot 的截图编辑、图片压缩和录屏能力。保留 Excalidraw 白板及其文件格式，新增截图工作流具有独立入口和文档类型。

必须保留：

- 自由绘图、图片插入、图形库、主题、画布背景、撤销与重做。
- `.excalidraw` 加载、保存、图片导出及剪贴板操作。
- 托盘、全屏/区域/窗口截图，以及现有 `CmdOrCtrl+Shift+A/S/W/E` 快捷键。
- 已有截图文件、设置与用户选择的存储位置；改变配置结构时提供迁移。
- 主窗口的现有行为；截图编辑器使用独立窗口，不直接替换透明白板。

当前未接通的文件列表、预览、设置和引导窗口作为待完成能力。Windows/Linux 适配已有缺口，不能视为可用基线。

先以 macOS 完成端到端体验；平台代码保留隔离，之后补齐 Windows/Linux。macOS 最低版本在原生采集验证任务中确定，不在依赖升级中隐式修改。

## 架构决定

| 层 | 职责 | 边界 |
| --- | --- | --- |
| React | 白板、截图编辑、历史、设置、压缩队列、录屏时间线 | 负责交互与编辑参数；不通过 IPC 搬运逐帧视频 |
| Rust / Tauri | 命令、任务状态、文件、项目存储、窗口、托盘、快捷键 | 校验文件访问与参数，统一成功、取消、失败状态 |
| macOS 原生模块 | 屏幕采集、权限查询、元素识别、媒体编码合成 | 先验证 Swift 桥接，再接入 ScreenCaptureKit / AVFoundation |

白板继续由 Excalidraw 渲染。截图编辑器的技术选型通过小规模验证决定：验证图片裁剪、标注定位、模糊和像素导出后，再决定复用 Excalidraw 的范围或采用独立 Canvas/WebGL 层。第一阶段不重写白板，也不预先引入完整渲染框架。

初期每个项目使用目录保存原始素材、版本化 JSON 和缩略图。历史列表由轻量索引维护，不立即引入数据库。写入采用临时文件加原子替换；启动时能恢复或识别中断写入。

截图模型分离原图、裁剪范围、图片变换、标注、背景和导出设置。标注坐标以源图像像素为基准，显示缩放和背景位置不改写标注坐标。多图使用独立图层变换，整体拼图具有独立画布坐标。

## 阶段 7：跨平台与发布

- 修复 Windows 模块路径、平台接口缺失和条件编译返回值；先建立对应系统的构建门禁，再实现采集。
- 逐项记录 Windows/Linux 能力，未实现的原生功能明确禁用，白板和通用图片编辑保持可用。
- Linux 分别验证 X11 与 Wayland，避免以 X11 验证结果代表全部 Linux。
- macOS Intel/Apple Silicon 打包、签名、公证与更新流程单独验收；公开发布在发布步骤执行。

## 每项功能的完成条件

1. 功能路径实际可运行，成功、取消、失败状态都能返回可继续操作的界面。
2. 涉及文档、坐标、时间或文件变更时，有覆盖边界情况的自动测试；测试不复述实现。
3. 在对应真实系统完成交互回归；无法验证的系统和权限场景明确列出。
4. 现有白板样例能加载、编辑、另存和导出，原始文件不被意外改写。
5. 更新此清单与验证记录，再提交该项改动。没有实现的能力不以占位按钮作为完成。
